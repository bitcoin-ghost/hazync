## The four faults it exposed

**1. 968,984 was skipped and nothing said so (#556).** It and 968,985 were mined 5 seconds apart, so
both bundles appeared at 13:24:59 and the selector — `highest_tip_bundle` — took the newest. Worse,
`work_fn` wrote `appeared` only for the height it selected, so 968,984 has no entry in the ledger at
all. The gap was absent from the session summary, the dashboard grid, the run log **and** the audit
trail built to catch exactly this. Fixed: prove the lowest unproved bundle, record every height seen,
and verify each bundle is the child of the last one proved before a GPU touches it.

**2. The dashboard published a board-fill number as a tip claim (#554).** `AHEAD OF CHAIN` took the
median over every proved block, and board bundles at the frontier are 16–370 KB against 27 MB for a
tip block. The frame showed **9.1×** where the tip blocks alone give **1.7×**. The grid disagreed the
whole time — it is anchored to the tip window, so board heights 837,000 below it can never appear —
which is why the frame read "19 blocks" beside a single filled cell.

**3. The live page spent the run showing a different run.** A collector from the previous attempt had
owned `snapshot.json` for 2h07m and this run's own collector had died, so the page rendered a fleet
that no longer existed (`0/20 up`, frozen spend). ⛔ **Both runs name their cards `hz-smoke-N`**, so
the only reliable test is the block heights: the snapshot's block was 131,817, which this run never
touched. Ask *which run is it publishing*, never *is it publishing*.

**4. `--cleanup` would have left nine cards billing (#557).** `rented.json` recorded 17 while the
fleet had grown to 26. A clean teardown hides it; the recovery path reads that file alone and would
have released 17, reported success, and left nine cards at ~$451/day.

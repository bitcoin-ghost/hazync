Byte-for-byte the same journal the x86-64 host reports for the same proof.

=== 2. NEGATIVE: a valid but NON-genesis proof must be REJECTED, on the pin ===

  $ qemu-aarch64-static -L /usr/aarch64-linux-gnu hazync-verify neg500.snark
  VERIFICATION FAILED: range starts at block 500, not 1 — NOT genesis-anchored
  [exit=1]

This is the assertion the whole artifact exists for. A smaller, more portable verifier that checked
LESS would be worse than the receipt it replaces — it would make a fabricated-anchor range easier to
circulate, not harder. The pin holds on ARM exactly as it does on x86-64.

=== WHAT THIS DOES AND DOES NOT SHOW ===

SHOWN: the verifier compiles for aarch64 with no source changes, produces a 1.6 MB binary, and both
verifies a genuine proof and rejects a fabricated anchor when executed as ARM64 code.

NOT SHOWN: execution on physical phone hardware, or an Android/iOS package. qemu-user executes real
aarch64 instructions against a real ARM64 libc, so the binary is genuinely ARM — but it is emulation
on x86-64, not a handset. Wall-clock timing under qemu is therefore NOT representative and is
deliberately not quoted here; on x86-64 native the same verification is sub-millisecond with 2.4 MB
peak RSS, and there is no reason for ARM to be materially different, but that remains an inference.

An Android build additionally needs the NDK (aarch64-linux-android target + NDK linker), which was
not available. That is packaging, not portability — the hard part is done.
